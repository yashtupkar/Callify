## 1. Current Architecture

### How a Call Flows Today

```
[Telnyx Telephony]
       │
       ▼
POST /api/telnyx/webhook
  → Returns TeXML with Stream url="wss://{host}/telnyx-media?to={calledNumber}"
       │
       ▼
WebSocket: /telnyx-media?to={phoneNumber}
  → telnyxConnectionHandler.js
  → Looks up phoneNumber in DB → finds Agent (if any)
  → Uses Agent.systemPrompt or hardcoded fallback
  → Creates ConversationManager(TelnyxChannelAdapter)
       │
[Browser WebSocket]
WebSocket: /
  → connectionHandler.js
  → Receives session.start { config } from frontend
  → Creates ConversationManager(BrowserChannelAdapter)
       │
       ▼
ConversationManager.startConversation(config)
  ├─ STT: STTService → Deepgram WebSocket (nova-2)
  ├─ LLM: LLMService → OpenRouter/OpenAI (GPT-4o-mini default)
  ├─ TTS: FishAudioTTSProvider or ElevenLabsTTSProvider
  └─ ToolExecutor + ToolRegistry (DISCONNECTED — see problem #4)

Audio In → STT → transcript → LLM → tokens → TTS → Audio Out
                               │
                        tool_call events
                               │
                    ToolExecutor.handle()
                          ├─ end_call
                          ├─ save_collected_data
                          ├─ built-in tools (registry)
                          └─ custom tools → frontend
```

### Call-Flow Step by Step

1. **Telephony Entry**: Telnyx POSTs to `/api/telnyx/webhook` → server returns TeXML streaming URL with `?to=<calledNumber>`
2. **Phone Number Lookup**: `telnyxConnectionHandler` queries DB: `PhoneNumber.findUnique({ where: { phoneNumber: to }, include: { Agent } })`
3. **Agent Config Load**: If found → uses `Agent.systemPrompt + Agent.voiceId`. If not → uses hardcoded fallback
4. **Prompt Assembly**: `CORE_VOICE_PERSONA + rolePrompt + date context + language + dataToCollect + closing rules`
5. **STT**: Deepgram WebSocket streaming (nova-2). Interim + final results. 500ms silence timeout triggers end-of-turn
6. **LLM**: OpenRouter (OpenAI-compatible). Streaming. Tool calls extracted from stream. Token usage tracked
7. **Tool Execution**: ToolExecutor handles `end_call`, `save_collected_data`, built-ins (via registry), or forwards custom tools to frontend
8. **TTS**: FishAudio (sentence-boundary batching) or ElevenLabs (WebSocket streaming). Raw PCM out
9. **Audio Return**: Channel adapter converts PCM → mu-law (Telnyx) or base64 PCM (browser)
10. **Session End**: DB saves CallSession with costs + transcript

## 5. Problems Identified

> [!WARNING]
> **No authentication on any API route.** Anyone can list, create, update, or delete agents. Critical gap for a multi-tenant platform.

> [!WARNING]
> **No workspace isolation.** Agents, phone numbers, and call sessions are globally shared with no ownership concept.

> [!CAUTION]
> **ToolRegistry and ToolExecutor exist but are NOT wired into ConversationManager.** The registry/executor were built as the better architecture but ConversationManager uses its own inline tool handling and hardcoded dentalTools instead. This is the most critical architectural disconnect.

> [!NOTE]
> **ConversationManager is a God Object** — 1067 lines (477 dead). It builds prompts, manages state, handles tools, manages TTS/STT/LLM lifecycle, and saves to DB. Needs decomposition.

> [!NOTE]
> **CallSession has no agentId** — impossible to query calls by agent for analytics.

> [!NOTE]
> **The `.env` file contains keys from a different project (PlaceMateAI)** — Razorpay, AWS, JDOODLE, Cloudinary, LiveKit, Brevo, etc. Only Callify-relevant keys should be in this file.

// Composable sections — each returns a string or null
function buildAgentPrompt({ agent, tools, timezone }) {
  const sections = [
    buildVoicePersonaSection(),       // CORE_VOICE_PERSONA (unchanged text)
    buildIdentitySection(agent),       // WHO the agent is
    buildGoalsSection(agent),          // WHAT it's here to do
    buildInstructionsSection(agent),   // Custom operator instructions
    buildBehaviorSection(agent),       // Tone, language, response style
    buildRulesSection(agent),          // Safety & business rules
    buildDataCollectionSection(agent), // What data to collect
    buildTemporalContextSection(timezone),
    buildToolUsageSection(tools),
    buildClosingSection(),
  ];
  return sections.filter(Boolean).join('\n\n---\n\n');
}

### Phase E — Agent Runtime Loader
**Risk: Low | Time: ~2h**

New file: `server/src/modules/agent/agentRuntime.js`

```js
async function loadAgentRuntime(agentId) {
  const agent = await db.agent.findUnique({ where: { id: agentId } });
  if (!agent) throw new Error(`Agent ${agentId} not found`);

  const registry = new ToolRegistry();

  // Register tools based on agent.agentTools config
  for (const tool of (agent.agentTools || [])) {
    if (tool.type === 'webhook') registerWebhookTool(registry, tool);
    // future: calendar, CRM, etc.
  }

  // Dynamic data collection schema
  if (agent.dataCollection?.length > 0) {
    registry.injectDataCollectionTool(
      agent.dataCollection.map(f => f.label)
    );
  }

  const systemPrompt = buildAgentPrompt({ agent, tools: registry.getAllSchemas() });

  return { agent, registry, systemPrompt };
}
```
